# ADR-0015 设计系统参照页独立于画廊

状态：已采纳

## 背景

画廊已经 fork 了 Beautiful UI 的组件，另外还有两份 Design System artifact：Beautiful UI 的上游文件表，和 Huabu 的静态卡片。把它们登记成 gallery 组件会和现有受控组件重复，也会把静态 HTML 塞进按工作划分的分类。画廊是组件库：页面切换只服务组件库自己的入口。设计系统是参照，不和 Gallery、Workflow、Harness 排成同一套页面。

## 决定

- 新增两张参照页，各绑定一份声明好的文件表快照：Beautiful UI、Huabu。绑定写死，不扫描目录。多一个文件夹不会多一页。地址是 `/design-systems/<id>`。
- 画廊左栏的页面切换只有 Gallery、Workflow、Harness。组件导航只列目录里的组件。设计系统不进这套切换，单独列在它下面，点进去离开画廊。`/workflow`、`/harness` 转回 `/?view=`。`/?view=beautiful-ui` 和 `/?view=huabu` 转到对应参照页。画廊的卡片、变体切换和分类导航不变（ADR-0009）。
- 参照页用自己的左栏：回到画廊的链接、两套系统之间的切换，以及该快照自己的分组。不使用画廊的名称口号，也不列出 Gallery、Workflow、Harness。
- 参照页的主题来自该快照的 `tokens.json`，作用域在该页，不写进 foundation。页内可以切换该系统自己的 light / dark，并跟站点主题保持一致。
- 读取是纯函数：一个系统目录进去，标题、主题、分组和卡片出来。这是第三条测试接缝。页面只渲染这个结果。预览在隔离框里，框只拿到该页的 token；声明了库和 bundle 的系统才加载它们。
- 快照放在 gallery 组件文件夹之外。不生成 `meta.json`，不进目录，不进 registry。上游标志只在所属参照页里当标本，不收成画廊自己的标志（ADR-0005）。
- Huabu 的卡片保持静态临摹。以后要收进画廊，仍按 ADR-0014 重画，不拷这些预览。

## 后果

- 画廊是组件库。参照页是另一处，一次看一套系统。
- 画廊组件仍以仓库里的受控组件为准。Beautiful UI 参照页上的 bundle 不是复制源。
- 快照是一次性收进来的文件表，不会跟着上游仓库自动更新。

## 备选

- 把两套系统的卡片登记为 gallery 组件。否决：Beautiful UI 已经在画廊里；Huabu 的预览不是受控组件，分类也装不下。
- 和 Gallery、Workflow、Harness 放进同一套页面切换，选中后只换右边的内容。否决：画廊是组件库，设计系统不该穿这套外壳。
- 跑 artifact 运行时来托管这两份系统。否决：画廊只需要读文件表并展示，不需要那套发布与评论能力。
