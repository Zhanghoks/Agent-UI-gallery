# ADR-0012 文档分工与文档一致性检查

状态：已采纳

## 背景

架构文档同时混着「最初的计划」与「已落地的现状」，ADR 状态与实现脱节，README 与架构文档对同一件事各写一遍，文档里引用的路径和命令没有任何东西保证真实存在，结果是文档悄悄过期。

## 决定

- 分工：
  - `docs/architecture.md`：只写现状；
  - `docs/roadmap.md`：尚未实现的设计与后续计划，每项有状态和对应 ADR；
  - `docs/adr/`：单项决策，固定结构「状态 / 背景 / 决定 / 后果 / 备选」，编号四位，状态只能是「已采纳 / 提议中 / 已被取代」；已实现的补充并入正文；
  - `CONTEXT.md`：术语表，词汇的唯一定义处；
  - `README.md`：用法，引用而不复制架构；
  - `docs/README.md`：文档入口索引，必须列出所有文档与 ADR。
- 文档一致性检查（`npm run docs:check`，并入 `npm test`）：文档里以行内代码出现的仓库路径必须存在；文档里的 `npm` 命令必须是真实脚本，且 README 必须覆盖 `package.json` 的每个脚本；每份 ADR 有合法的编号、标题、状态和三个固定章节；索引列出全部文档。围栏代码块（如目录树）不检查；`docs/agents/` 是技能工具生成的文件，只要求被索引。
- 沿革性叙述、生成文件路径、示例路径可以用同一行末尾的 `<!-- docs-check-ignore: 原因 -->` 豁免，原因必填。
- 检查是第二个测试接缝，输入仓库根目录，输出问题列表。

## 后果

- 文档与仓库不一致时提交前就能发现。
- 沿革说明要么改写成不引用旧名字，要么写明豁免原因。
- 文档措辞、排版、术语是否恰当仍靠人工评审，检查不覆盖。

## 备选

只靠评审保证文档准确。否决：上一轮迁移里文档就在多处与实现脱节。
